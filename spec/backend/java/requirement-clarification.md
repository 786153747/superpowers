# 需求澄清清单（后端补充）

> 适用于当前若依后端；通用问题先看 `spec/guides/requirement-clarification.md`，这里补充后端落地时最容易遗漏的仓库级问题。

## 1. 接口与权限

- [ ] 新接口还是改旧接口？具体路径、HTTP 方法是什么？
- [ ] 接口 owner / 所属模块 / Controller-Service 边界由谁负责？
- [ ] 对应权限标识是什么？是否需要同步菜单权限、按钮权限？
- [ ] 返回 `AjaxResult` 还是 `TableDataInfo`？是否包含导出 / 导入接口？
- [ ] 是否需要放到已有 Controller，还是新增 Controller？

## 2. 业务规则

- [ ] 新增 / 修改 / 删除的校验规则是什么？
- [ ] 是否存在唯一性约束、状态流转、幂等要求？
- [ ] 删除是软删还是物理删？若软删，是否沿用 `del_flag`？
- [ ] 是否存在数据范围限制，需要 `@DataScope` 吗？

## 3. 数据模型与 SQL

- [ ] 是否新增表 / 字段 / 索引？
- [ ] 表是否需要标准审计字段与 `remark`？
- [ ] 是否需要 `status`、`del_flag`、树结构字段（`parent_id` / `ancestors`）？
- [ ] SQL 是否需要联表查询、分页、模糊查询、时间范围过滤？
- [ ] 前端字段、DTO、DO、表字段之间如何映射？是否存在名称转换或派生字段？
- [ ] 枚举 / 字典值来源是什么：系统字典、配置表、硬编码枚举还是外部服务？
- [ ] 数据最终写入哪些表 / 字段？是否还会旁路写入日志、明细表、关联表或异步任务？
- [ ] 字段联动与派生值由谁兜底：前端切换后哪些字段必须清空、重算、拒绝提交，后端是否需要二次校验？

## 4. 与现有若依能力的关系

- [ ] 是否需要接入操作日志 `@Log`？
- [ ] 是否涉及 Excel 导入导出？
- [ ] 是否复用现有字典、配置参数、上传下载能力？
- [ ] 是否适合先用若依代码生成器起手？

## 5. 安全与异常

- [ ] 参数校验放在哪里：Bean Validation、Service 校验还是数据库约束？
- [ ] 业务异常如何提示？是否直接抛 `ServiceException`？
- [ ] 是否涉及敏感字段、脱敏、权限隔离、风控或限流？
- [ ] 审计字段由谁维护：框架自动填充、业务代码赋值，还是数据库默认值？

## 6. 验收与回归

- [ ] 成功标准是什么？主流程和异常分支分别如何验收？
- [ ] 需要联调哪些前端页面或菜单？
- [ ] 是否需要补 SQL 脚本、菜单初始化数据、字典数据？

```md
- 已确认：

- 假设：
- 涉及文件：

- 涉及权限：
```
