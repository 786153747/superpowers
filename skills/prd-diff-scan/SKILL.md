# PRD 差异扫描

## 概述

逐页面、逐要素对比 PRD 与当前项目实现，产出页面级证据，而非模块级总结。

本 skill 通常由 `brainstorming` 在步骤 2 自动调用。也可以单独使用。

对比方式统一为 **PRD ↔ 当前实现** 双方对比。

## 结束边界

如果用户明确表达以下任一意图：

- 只做差异扫描 / 只生成 diff 文档
- 不要进入 brainstorming / plan / 编码
- 先出差异分析结果，后续再说

则本 skill 在**步骤 7 落盘后必须立即停止**，不得自动调用或跳转到 `brainstorming`。

此时只允许输出类似 checkpoint：

```
✅ 差异扫描完成，文档已保存到 `docs/plans/YYYY-MM-DD-<主题>-diff.md`。
如需继续设计，请明确要求进入 brainstorming。
```

只有以下情况才允许进入下一阶段：

1. 本 skill 是由 `brainstorming` 明确作为前置步骤调用；或
2. 用户在差异扫描完成后，明确要求继续进入设计/brainstorming；或
3. 用户明确说明这是**自动测试 / 非交互**场景，并且明确授权：若无 blocker，差异扫描落盘后自动继续进入 brainstorming / 详细设计，无需逐轮等待确认。

## 自动测试 / 非交互模式（窄例外）

只有同时满足以下条件，才能启用这个模式：

- 用户明确说这是自动测试、CI、批处理或非交互场景
- 用户明确说：没有 blocker 时，默认采用推荐方案
- 用户明确说：默认同意继续下一步、默认同意落盘

启用后：

- 步骤 7 落盘后，如果**没有未解决 blocker**，可以直接继续进入 brainstorming / 详细设计
- 如果还有 blocker、关键信息缺失、PRD 与现状冲突无法自动决策，必须停止并把问题写清楚
- 不能把"自动测试"理解成"可以忽略证据不足"

## 证据原则

- **先记录证据，再下结论**：每个结论都要能追溯到 PRD 或代码文件
- **PRD 中无法明确的逻辑**：接口、权限、数据流向、状态流转、默认值来源等，若无法从 PRD 文字中确认，标记为 `待确认` / `Blocker`
- **不得脑补业务规则**：PRD 没写的，不能自行补全

## 前置条件

用户必须提供以下至少一项：
- PRD 文档（本地文件路径）
- 粘贴的需求描述
- 外置规范文档

如果用户没有提供，告知用户："请提供 PRD 或需求文档的路径"，然后等待。

---

## 步骤 1：读取需求文档

1. 用 Read 工具读取用户提供的 PRD / 需求文档
2. 如果项目中存在 `spec/index.md`，也读取它
3. 记录所有读取的文件路径

输出：

```
## 需求输入
- PRD: [文件路径]
- 项目规范: [spec/index.md 或 "无"]
```

---

## 步骤 2：探索现有实现

用 Agent（Explore 类型）或 Glob/Grep/Read 探索项目，找出与需求相关的现有代码。

必须了解：
- 哪些页面 / 接口 / 表已存在
- 哪些完全不存在
- 技术栈

**关键：必须用 Read 工具读取每个已存在页面文件的完整源码。** 仅确认文件存在而不读取内容是不够的——步骤 4 需要对比页面上的每个控件、字段、交互行为，不读源码就无法做真实对比。

如果页面文件较多，可以分批读取，但**进入步骤 4 之前必须确保所有已存在的页面文件都已读取**。

输出：

```
## 项目现状
- 技术栈: [如 Vue 3 + Spring Boot + MySQL]
- 已有实现: [列出文件路径]
- 未实现: [列出缺失部分]
```

---

## 步骤 3：列出受影响页面

先列出 PRD 涉及的所有页面 / 流程，标注核对状态：

```
## 受影响页面清单

| 页面/流程 | 当前实现文件 | 核对状态 |
|-----------|-------------|---------|
| [页面名] | [文件路径或"不存在"] | 未核对 |
```

---

## 步骤 4：逐页面对比（核心）

对每个页面，依次检查以下内容。

**禁止「待核对」作为对比结论。** 每个单元格必须填写明确结论：一致 / 差异 / 缺失 / 新增 / 部分差异。如果某页面文件存在但源码未读取，必须先回到步骤 2 读取，然后才能填写对比表。对比表中出现「待核对」「需核对」等未决结论 = 差异扫描未完成，不得落盘。

### 4.1 UI 可视要素对比

```
### [页面名称] — UI 可视要素对比

| 要素 | PRD | 当前实现 | 结论 | 是否阻塞 |
|------|-----|---------|------|---------|
| 页面标题 | [描述] | [描述] | 一致/差异 | 是/否 |
| 筛选区 | [描述] | [描述] | 一致/差异 | 是/否 |
| 表格结构 | [描述] | [描述] | 一致/差异 | 是/否 |
| 表单布局 | [描述] | [描述] | 一致/差异 | 是/否 |
| 按钮/工具栏 | [描述] | [描述] | 一致/差异 | 是/否 |
| 状态标签/提示文案 | [描述] | [描述] | 一致/差异 | 是/否 |
| 空态/占位/默认展示 | [描述] | [描述] | 一致/差异 | 是/否 |
```

### 4.2 控件矩阵

在 UI 可视要素对比之后，必须输出**控件矩阵**。这里的"控件"指页面上可见且影响实现判断的业务控件/要素，而不是前端源码里的组件树节点。

控件矩阵最少覆盖以下类别：筛选控件、表格列、按钮/菜单、状态标签、弹窗/抽屉入口、分页/工具栏、空态/提示文案。

```
### [页面名称] — 控件矩阵

| 控件类别 | 控件名称/文案 | 所在区域 | PRD | 当前实现 | 结论 | 是否阻塞 |
|---------|--------------|---------|-----|---------|------|---------|
| 筛选控件 | [如: 状态下拉] | [查询区] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
| 表格列 | [如: 可用库存] | [列表表格] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
| 按钮/菜单 | [如: 导出] | [工具栏/行操作] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
| 状态标签 | [如: 已发货] | [列表/详情] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
| 弹窗/抽屉入口 | [如: 订单确认] | [行操作/顶部按钮] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
| 分页/工具栏 | [如: 分页器/RightToolbar] | [表格底部/顶部] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
| 空态/提示文案 | [如: 暂无数据] | [表格空态/弹窗] | [描述] | [描述] | 一致/差异/缺失/新增 | 是/否 |
```

要求：

- 不得只写"页面看起来差不多"，必须落到具体控件/要素
- 同一页面内控件较多时，可以按"查询区 / 表格区 / 操作区 / 弹窗区 / 详情区"分组输出多张矩阵表

### 4.3 字段对比

每个页面按 4 个区域对比：

```
### [页面名称] — 字段对比

| 区域 | PRD 要求 | 当前实现 | 结论 | 是否已核对 |
|------|---------|---------|------|-----------|
| 查询条件 | [字段列表] | [字段列表] | 一致/差异 | 是/否 |
| 表格列 | [列名列表] | [列名列表] | 一致/差异 | 是/否 |
| 表单字段 | [字段列表] | [字段列表] | 一致/差异 | 是/否 |
| 行操作/按钮 | [按钮列表] | [按钮列表] | 一致/差异 | 是/否 |
```

说明：`查询条件 / 表格列 / 表单字段 / 行操作/按钮` 属于**字段对比表**，不计入下面的 **9 大维度**。`控件矩阵` 也不计入 9 大维度，它用于把页面上的业务控件/要素拆到更细粒度。

### 4.4 交互 / 联动对比

每个页面按 **9 大维度** 逐项检查：

| 维度 | 检查内容 |
|------|---------|
| **交互行为** | 按钮、菜单、弹窗、跳转、返回路径、二次确认 |
| **触发事件** | 点击、切换、分页、搜索、自动刷新、定时触发 |
| **数据来源** | 接口、字典、枚举、配置、外部系统、静态常量 |
| **数据流向** | 展示字段来自哪里，提交后落到哪里 |
| **字段联动** | 显隐、禁用、必填切换、联动清空、级联请求、自动带出 |
| **状态流转** | 状态机、启停、草稿/发布、异常分支 |
| **权限与角色** | 谁可见、谁可操作、按钮/菜单/接口权限归属 |
| **默认值 / 排序 / 回显** | 默认选项、默认排序、默认分页、初始化条件、回显来源 |
| **下拉/字典来源** | 固定值、字典接口、级联依赖、label/value 结构 |

每个页面输出：

```
### [页面名称] — 交互/联动对比

| 维度 | PRD 要求 | 当前实现 | 结论 | 是否阻塞 |
|------|---------|---------|------|---------|
| 交互行为 | [描述] | [描述] | 一致/差异 | 是/否 |
| 触发事件 | [描述] | [描述] | 一致/差异 | 是/否 |
| 数据来源 | [描述] | [描述] | 一致/差异 | 是/否 |
| 数据流向 | [描述] | [描述] | 一致/差异 | 是/否 |
| 字段联动 | [描述] | [描述] | 一致/差异 | 是/否 |
| 状态流转 | [描述] | [描述] | 一致/差异 | 是/否 |
| 权限与角色 | [描述] | [描述] | 一致/差异 | 是/否 |
| 默认值 / 排序 / 回显 | [描述] | [描述] | 一致/差异 | 是/否 |
| 下拉/字典来源 | [描述] | [描述] | 一致/差异 | 是/否 |
```

此外，每个页面必须补充一个**验收点**小节。`验收点` 不计入 9 大维度，但如果未核对，必须出现在"未核对项"里，并可直接判定为 `Blocker`。

```
### [页面名称] — 验收点

- 正向场景: [描述]
- 空态: [描述]
- 异常态: [描述]
- 权限态: [描述]
```

### 4.5 未核对项

如果某个页面或维度尚未检查，必须列出：

```
## 未核对项
- 页面: [名称]
  - 未核对维度: [列表]
```

未核对维度自动视为 Blocker。

## 步骤 6：汇总差异 + Blockers

```
## 差异清单

| 编号 | 差异描述 | 差异类型 | 影响范围 | 是否阻塞 |
|------|---------|---------|---------|---------|
| D1 | [描述] | [可视要素/字段/9维度之一] | 前端/后端/数据库 | 是/否 |

## Blockers（需用户确认）

1. **B1**: [问题] — 建议: [选项]
2. **B2**: [问题] — 建议: [选项]

## 建议决议（逐项待确认）

从 D1 到 D{最后编号} 和 B1 到 B{最后编号} **必须逐行不间断列出**，不得跳过任何编号：

| 编号 | 差异/问题摘要 | 建议处理方案 | 用户确认 |
|------|-------------|-------------|---------|
| D1 | [差异描述] | [保持现状 / 按 PRD 修改 / 其他] | ⏳ 待确认 |
| D2 | [差异描述] | [方案] | ⏳ 待确认 |
| ... | （从 D1 到 D{N} 每个都要列） | ... | ... |
| B1 | [Blocker 描述] | [方案 A / 方案 B] | ⏳ 待确认 |
| ... | （从 B1 到 B{M} 每个都要列） | ... | ... |

> **统计行（必填）**：本表共 __ 行 = D1-D{N} 共 __ 项 + B1-B{M} 共 __ 项

如果差异清单有 D1-D12 共 12 项、Blockers 有 B1-B6 共 6 项，则此表必须有 18 行，**缺一行即不合格**。

## 差异决议

用户逐项确认后，将上表「用户确认」列更新为 ✅ + 用户选择的方案。
全部确认后方可进入 brainstorming。
```

**差异类型** 从以下类型中选填：可视要素 / 控件 / 字段 / 交互行为 / 触发事件 / 数据来源 / 数据流向 / 字段联动 / 状态流转 / 权限与角色 / 默认值 / 排序 / 回显 / 下拉字典来源 / 验收点

### 差异清单完整性规则

差异清单必须**完整反映**步骤 4 和步骤 5 中发现的所有差异：

1. **逐行扫描**：步骤 4 每张对比表中，「结论」列为「差异」「缺失」「新增」「部分差异」的每一行，都必须在差异清单中有对应的 Dx 编号
2. **后端同步**：步骤 5 的接口/数据库对比表中，「是否一致」为「否」的每一行，也必须有对应 Dx
3. **禁止合并**：不同页面、不同维度的差异不能合并成一条笼统描述（如「前端部分实现」「后端未实现」不能代替逐项差异）
4. **Blocker 同步**：差异清单中「是否阻塞=是」的每一条，必须在 Blockers 列表中有对应 Bx
5. **建议决议覆盖**：建议决议表必须从 D1 到 D{最后编号}、B1 到 B{最后编号} 逐行列出，不得跳过任何编号
6. **追溯校验**：完成差异清单后，必须**回看**步骤 4-5 每张对比表，逐行确认每个「差异/缺失/新增/部分差异」行都能追溯到某个 Dx。如果发现遗漏，立即补充 Dx

违反此规则 = 差异扫描不合格，必须补全后重新落盘。

## 步骤 7：落盘

### 落盘前自检（必须执行）

保存前必须对照以下清单逐项自检。**必须填入实际数字**，不得只写 ✅ 或"已完成"。任一项不通过则补全后再保存。

```
## 落盘前自检

| # | 检查项 | 实际结果（必须填数字） | 通过? |
|---|--------|----------------------|------|
| 1 | 页面完整性: PRD 涉及 __ 个页面，文档对比了 __ 个页面 | [填入两个数字] | ✅/❌ |
| 2 | 维度完整性: | [逐页列出] | ✅/❌ |
|   | - 页面1 [名称]: UI可视要素 ✅/❌, 控件矩阵 ✅/❌, 字段对比 ✅/❌, 9维度 ✅/❌, 验收点 ✅/❌ | | |
|   | - 页面2 [名称]: ... (每页一行) | | |
|   | **注意：如果任何维度表格内存在「待核对」「需核对」结论，该维度视为 ❌** | | |
| 3 | 差异映射: 对比表中「差异/缺失/新增/部分差异」共 __ 行 → 差异清单共 __ 条 Dx | [填入两个数字，前者 ≤ 后者] | ✅/❌ |
| 4 | Blocker 同步: 差异清单中「是否阻塞=是」共 __ 条 → Blockers 共 __ 条 Bx | [填入两个数字，必须相等；禁止多条阻塞差异归纳成一条 Bx] | ✅/❌ |
| 5 | 建议决议覆盖: 决议表共 __ 行 ≥ Dx __ 条 + Bx __ 条 = __ | [填入数字并验算] | ✅/❌ |
| 6 | 未核对项: 有 __ 个未核对的页面/维度，已标记为 Blocker: 是/否 | [填入数字] | ✅/❌ |
```

**自检格式要求**：
- 每个 `__` 处必须替换为实际数字
- 检查项 2 必须逐页展开，不得写"所有页面已完成"
- 检查项 3 的左侧数字（对比表差异行总数）需要实际回看每张表逐行计数
- 检查项 4 要求**阻塞差异数 = Blocker 数**，禁止把多条阻塞差异归纳成一条笼统 Blocker（如"后端完全缺失"不能合并 D3-D8 六条接口 Mock 差异）
- 任何一项为 ❌ 时必须补全，补全后重新自检

### 保存

把以上全部内容保存到 `docs/plans/YYYY-MM-DD-<主题>-diff.md`。

差异扫描结果必须落盘，不能只存在于聊天记录中。

落盘后执行以下分支：

- **Standalone 模式**（用户只要差异扫描）：输出保存路径后 `STOP`，等待用户下一步指令
- **brainstorming 前置模式**：告知差异扫描已完成，可返回 `brainstorming` 继续后续设计
- **自动测试 / 非交互模式**：若无未解决 blocker，差异扫描落盘后可直接继续进入 brainstorming / 详细设计

---

## 冲突判定规则

以下情况必须标记为 Blocker：

- PRD 定义了当前实现中未展示的行为
- PRD 和当前实现在字段含义、触发条件、数据流向上不一致
- PRD 中无法明确的控件状态、数据来源、权限、状态流转、默认值 / 排序 / 回显来源被模型自行补全
- 外置 spec 与 PRD / 现状有矛盾
- 任何页面维度未核对
- "差异决议"只能记录用户已确认的结论，不可自行拍板

## 反面示例

以下输出**不合格**：

